CONTEXT:
This project was initially intended as a personal learning opportunity rather than a professional GitHub project. 
This is the main reason I decided to keep the language and flow of this README very simple.

Even though the original plan was only to learn Git and API basics alongside a functional project,
it has grown into a template for my future large-scale projects in the same domain. 
It also works as a test platform for penetration testing and for learning the basics of being a SOC analyst and a security engineer.

SETUP:
The setup for this project is simple. You need a code editor, Git Bash, and XAMPP.

KNOWLEDGE REQUIREMENTS:
This project uses PHP and Python as the main languages. Having some prior knowledge of the basics helps a lot. 
Personally, I spent an hour learning API basics and another hour learning Git and Git Bash basics. 
I already had prior knowledge of PHP and Python. The rest I explored gradually throughout the project.

WORKING AND FILES:
The project is a mini SIEM (Security Information and Event Management), which is a concept in cybersecurity.
A normal user uses the register.php file, which shows a registration page with an option to navigate to the login page.
User information is stored in a MySQL database running through XAMPP and is fetched from the database in multiple places.
The main.py file has to be run manually to inspect logs and look at threats. 
You can also set main.py to run automatically at regular intervals, but for a personal experimental project I decided to keep that in my own hands.

CONCLUSION:
An API key is used for security reasons and since the project mainly focused on backend concepts and security, the CSS part was mostly handled by some prompts. 
Because this is a practice project, you have to run it on your own system.Also, by the time you see this repository it may have changed multiple times, or it may
